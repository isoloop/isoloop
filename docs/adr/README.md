# Architecture decision records

Short records of decisions that shape Isoloop's design. Each has a status:

- **Proposed:** a recommended default, open to review.
- **Accepted:** binding; change it only with a new ADR that supersedes it.
- **Rejected / Superseded:** kept for history.

| ADR | Decision | Status |
| --- | --- | --- |
| [0001](0001-one-worker-per-isolate.md) | Own worker per isolate by default; opt-in named pools (field reserved in v1, built in M2c); opt-in suspension (`suspend`); soft worker budget. Amended 2026-11-20: a warm-up window after `ready`, killing a blocked isolate only after `readyTimeoutMs` | Accepted |
| [0002](0002-host-owns-routing.md) | The host owns the URL; isolates opt in to `isoloop.route.v1` and need a grant to `navigate`; `kernel.syncRoute()`, `basePath`, routing can be turned off | Accepted |
| [0003](0003-schema-format-standard-schema.md) | Standard Schema at runtime (required, validated in the broker, output stored), contracts URL as the single source, topics seeded from older versions, JSON Schema exported for tools | Accepted |
| [0004](0004-npm-name.md) | Project renamed Federa → Isoloop; `@isoloop/*` packages | Accepted |
| [0005](0005-bus-topology-message-channels.md) | Isolates talk to the bus worker over direct `MessageChannel`s | Accepted |
| [0006](0006-render-bridge-over-remote-dom.md) | Remote DOM sits behind an internal `RenderBridge`; events use Isoloop's own protocol | Superseded by 0010 |
| [0007](0007-bus-worker-supervision.md) | Bus worker is supervised; isolates reattach after a bus crash; per-topic durability in OPFS (no replicas) | Accepted |
| [0008](0008-isolates-and-surfaces.md) | The unit is an *isolate*; a *surface* (DOM) is optional, so headless isolates are first-class | Accepted |
| [0009](0009-toolchain.md) | Toolchain: pnpm 12 workspaces, Node 26, TypeScript 7 (`tsc` checks), oxlint + oxfmt, tsdown with `isolatedDeclarations`, Vite 8, Vitest 5, Playwright; Baseline widely available; exact pins, no hooks | Accepted |
| [0010](0010-own-render-bridge.md) | Our own render bridge, `isoloop-dom@1`: a worker-side DOM subset sized to what Preact and React use, plain id-based records with one-record moves, no dependency; supersedes 0006. Amended 2026-11-16: Vue, Svelte and Solid after 0.1 (M6), Vue spike first, HTML parsing and `cloneNode` in the worker with no format change | Accepted |
| [0011](0011-dom-package.md) | `@isoloop/dom` holds the bridge: `/worker`, `/host` and `/testing` entries, each half type-checked with its own `lib`; no runtime dependencies; owns the `isoloop-dom@1` format; sanitising policy passed in; exact fmt match; published as internal; every `@isoloop/*` package in one `fixed` release group | Accepted |
| [0012](0012-isolates-built-apart.md) | Isolates built apart from the host are supported: the seam (`ctx`, the DOM subset, adapter hooks) only grows, isolates are stamped with `requires`, and the host runs `[FLOOR, VERSION]` (`runtime-too-old`, `isolate-too-old`) | Accepted |
| 0013 | *Withdrawn 2026-11-07, never accepted:* `@isoloop/local`, a single-thread kernel for the M3b comparison. The comparison is native against Isoloop instead ([M3b plan](../plans/m3b-dashboard.md), task 15), so no such kernel is needed | Withdrawn |
| [0014](0014-own-codec.md) | Our own binary codec for persistent topics, `isoloop-codec@1`: no library was more than 2× faster (at most 1.42×), ours is smaller on the wire and in the bundle | Accepted |
| [0015](0015-visual-pools.md) | Visual isolates may join pools: one `isoloop-dom` document per worker, one render root per member; records, events and host calls carry the member; no moves between members; mixed pools and mixed frameworks allowed; members can read each other's DOM and input (secrets stay on their own worker); a portal root per member; gate on memory, start-up and update latency first (M2d task 1); amended 2026-11-16: a stopped member's timers, frames, idle callbacks, microtasks and port listeners no longer run | Accepted |
| [0016](0016-fewer-messages-per-record.md) | Fewer bus messages per record: subscribers' settled offsets go out together as one `commits` per port per `KernelConfig.bus.commitIntervalMs` (default 100 ms; earlier at half the credit, and on shutdown, waiting for the broker; none sent first after a bus restart); measured −20% port messages. Batching per port (built, measured, removed) and publishes answering only on failure (not taken) are recorded with why; one delivery per pool worker deferred, opt-in per pool if ever done Amended 2026-11-17 (accepted, #211): commits carry a delivery `seq`, so a group commit can't cover a record redelivered after it, and a group that has committed resumes from its committed offset whatever `from` says | Accepted |
| [0017](0017-opt-in-balancer.md) | An opt-in, host-side `@isoloop/balancer` (`@experimental`), one per kernel, places isolates spawned through it into pools it owns (the `balancer-` prefix, reserved by the host: `reserved_pool`, `claimPools`), from a new public per-member `busyMs`: a spike or crash sends the culprit to a quarantine pool, sustained load moves the heaviest member to a pool with room, a kill with no known culprit is bisected; predicted-load placement (< 60 %), its own worker cap, cooldowns; moves are stop then spawn. Amends 0001 and 0015: the runtime still never pools on its own. `busyMs` is attributed by wrapping timers, rAF, `queueMicrotask`, `requestIdleCallback` and member ports in every worker, plus a minimal React DevTools hook and Preact `options` hooks, with shared tasks split equally; a placement guide, not a profiler | Accepted |
| [0018](0018-tools-for-agents.md) | Tools for agents (`@experimental`): a requestable topic may carry a `tool` field (`description` and `readOnly` required); the app exposes tools with `agents.expose` (checked at start, `not_exposable`); a public `kernel.request` with `signal` and `via` on the record; agent calls time out after 10 s, fail at once with `no_responder` when nobody can answer, and need idempotent handlers; two transports in their own entries: `connectDevMCP` (dev only, token + Origin pairing, a production build guard in `@isoloop/vite`) and `@isoloop/webmcp`'s `connectWebMCP`. Amends 0003 (JSON Schema at run time). Amended 2026-11-19: Firefox's WebMCP supported next to Chromium's, `document.modelContext` then `navigator.modelContext`, hints sent only when true, a duplicate tool name fails with `invalid_config` (decision 8, *Browsers that differ*). Amended 2026-11-20: a request that retention removes before any subscriber gets it fails at once with `dropped` (decision 5) | Accepted |
| [0019](0019-versioning-and-releases.md) | Versioning and releases: one shared version for every package; `0.1.0-next.N` previews under npm `next` (Changesets pre mode), then `0.1.0` under `latest`; on 0.x a minor may break anything outside the isolate seam and is needed for any seam addition, a patch is fixes plus compatible additions outside the seam; `@experimental` may change in any minor, before and after 1.0; patches during a preview cycle come from a `release/0.x` branch cut on demand; every published version is tagged `v<version>`, only unsuffixed tags release; CI blocks a `major` changeset below 1.0 without the `release-1.0` label and passes version PRs on their own; the `0.0.0*` versions are deprecated | Accepted |
| [0020](0020-inspection-feed.md) | Inspection feed (`@experimental`): `kernel.inspect()` gives a snapshot of isolates, pools and the bus, then events (beats and bus metrics coalesced to 1 s), as plain messages in one format for every reader; records through a bus `tap` (not a consumer, 50/s) and a `read` (last 100), values cut to 2 KB previews; memory per isolate from the host's `measureUserAgentSpecificMemory()` when cross-origin isolated (Chromium); a runtime `block { ms }` (≤ 10 s); a ring buffer of the last 200 events from start; an `inspect` grant, refused in pools, with `ctx.inspector` on a host↔isolate port that survives a bus restart and carries kill, block and restart. Amended 2026-11-18 (the isolate side, memory from the host) and 2026-11-19 (`onSkipped` on `tap`) | Accepted |

Ideas an ADR deferred are collected in [would-like](../would-like.md).
