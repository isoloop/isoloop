# M4c: Docs (epic of [M4](m4-devtools-release.md), outline)

**Goal:** the docs on isoloop.dev, readable by people and by agents.

**Done when:** the docs are live on isoloop.dev, with `llms.txt`, `llms-full.txt` and a Markdown copy of each page, and the API reference built from the frozen API.

**Status (2026-11-19):** next to start, now that M4a's and M4b's public API is merged. What exists already, in `docs/guide`: hosting (since M1), worker pools, the balancer, devtools, inspection and agents. Not written yet: getting started (with the users' `AGENTS.md` snippet), isolate authoring per adapter, the bus guide, "Build a dev tool as an isolate" and "What Isoloop can't hide"; the docs site and `llms.txt` aren't started either.

Gets a full task list when it's next to start. The guides that don't depend on frozen names can start any time; the API reference waits for [M4d](m4d-release.md)'s freeze.

## Main work items

1. **The docs site,** built in `isoloop/web` and served at `isoloop.dev` (*amended 2026-11-14:* no longer `docs/site` in this repo). The guides and TSDoc stay here, and `web` fetches them at the release tag. The engine is chosen in an ADR there, behind an interface it owns, per `isoloop/web` ADRs 0002 and 0003.
2. **Guides:**
   - getting started, with an `AGENTS.md` snippet for users' apps ([M4a](m4a-agents.md), decision 16; the repos' own `AGENTS.md` are M4a task 11, and the snippet waits for this guide);
   - hosting (CSP/CORS);
   - isolate authoring per adapter;
   - the bus guide (semantics, idempotent handlers);
   - **"Agents":** exposing tools, the dev MCP (`claude mcp add isoloop -- npx isoloop mcp`, `.mcp.json`), `@isoloop/webmcp`, idempotent tool handlers, and what the annotations do and don't do (Firefox's agent doesn't see `consequentialHint` or `untrustedContentHint`, ADR 0018 decision 8, checked by `e2e/webmcp.spec.ts`'s registration case in `firefox-webmcp`, isoloop#267);
   - **"Build a dev tool as an isolate,"** with `@isoloop/devtools` as the worked example: tools that read only the app's own topics need no grant, and tools that read the kernel's feed need `inspect`;
     - *Drafted 2026-11-19:* the Agents guide is [`docs/guide/agents.md`](../guide/agents.md), and the inspection feed has its own guide, [`docs/guide/inspection.md`](../guide/inspection.md) (`kernel.inspect()`, the `inspect` grant, `ctx.inspector`, the controls, memory per isolate, the measured cost). The dev-tool guide builds on both; M4b task 11 is done (2026-11-19), so it can start. The panel itself has a guide, [`docs/guide/devtools.md`](../guide/devtools.md).
   - **"What Isoloop can't hide"** (sync layout, `window`/`document` globals, drag and drop), up front, as the RFC asks.
3. **API reference** generated from TSDoc, after the freeze.
4. **`llms.txt`, `llms-full.txt` and a `.md` copy of each page,** generated by the same docs build at each `site-v*` deploy, so they can't go stale (decided 2026-11-17). `llms.txt` is an index (one line per page with a description) that links to the skill; `llms-full.txt` holds all guides plus the API reference.
