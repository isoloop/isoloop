Gates, in order

  • Grants: an isolate publishes only to topics its grants list; isoloop.* system topics are the kernel's alone (forbidden).
  • The topic must exist (unknown_topic), have a reply schema for a request (not_requestable) and fit its size limit (too_large).
  • Schema: invalid returns issues; an async schema still appends in publish order.
  • Persistent topics: a re-send already on disk gets its original offset, then the value must encode (not_encodable) and storage must have room (quota_exceeded).

Answers to the producer

  • Every publish gets a result: its offset, or the error.
  • Memory topics answer at append; persistent topics after the batch is on disk.
  • Requests append like publishes, with req on the record; the first valid reply comes back as the request's result.

Delivery and commits

  • The broker delivers from each subscription's cursor while it has credit; at 0 it pauses and a commit resumes it.
  • Records that expired before delivery arrive as a gap.
  • Each port sends one commits message with every subscription's settled offset, at most every commitIntervalMs (100 ms), earlier at half the credit, and awaited on shutdown (ADR 0016). A handler that throws stops its subscription's commits.
