How to read it

  • Isolate code never touches the page. It changes a document in its worker; the changes travel as isoloop-dom@1 records, and the compositor is the only code that writes to a surface.
  • The bold arrows are a frame on its way out; dashed arrows come back to the worker: an event, or a host call's result.

A frame

  • Every change in one microtask becomes one batch, sent as one patch with any new stylesheets from ctx.styles.
  • One requestAnimationFrame applies the queued batches round-robin across surfaces while the budget lasts, 8 ms by default (KernelConfig.compositor). The first batch of a frame always applies; batches are never split.
  • The registry turns unknown tags into div, never creates script-capable tags or on* attributes, and allows only http(s), mailto and relative URLs. KernelConfig.components maps a tag to a host custom element.

Events back

  • Forwarded as they happen: click, dblclick, input, change, keydown, keyup, submit, focusin, focusout, pointerdown, pointerup.
  • Coalesced to one per frame: pointermove, and scroll per scrolled node.
  • Only to nodes with a listener for that type. submit is always prevented on the host. With routing on, plain clicks on same-origin links go to the router.

Host calls and pools

  • measure, focus and scrollIntoView run after every batch sent before them, so measure sees their layout. requestCanvas hands a rendered canvas over as an OffscreenCanvas, once.
  • Styles: KernelConfig.styles in every surface, then the isolate's own sheets; neither leaks out of the shadow root.
  • In a pool, the visual members share one document with a root each; each root has its own recorder, and its patches name the member.
